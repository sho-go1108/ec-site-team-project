工夫した点
1. 絞り込み条件を URL で管理
カテゴリ・並び順・ページ番号を URL のクエリパラメータで管理しました。ページを再読み込みしたり、URL を共有したりしても同じ表示になります。 初期値（「全て」「新着順」「1ページ目」）はクエリから省き、URL が短くなるようにしています。 不正な値（page=-1 や存在しない並び順など）が来ても、初期値に戻して安全に表示します。

2. Server Components でのデータ取得
トップページと商品一覧は Server Components で作り、カテゴリと商品を Promise.all で並列に取得して表示を速くしています。 API エラーと通信エラーを分けて、ユーザーに分かりやすいメッセージと再読み込みボタンを出します。

3. 画像が読めないときの代替表示
商品画像の URL が空のときや読み込みに失敗したときは、代替画像（No Image）に切り替えます。 レビューで「商品が切り替わってもエラー状態が残る」と指摘を受け、商品 ID が変わったらエラー状態をリセットするよう修正しました。

4. アクセシビリティ
選択中のカテゴリ・ページに aria-current="page" を付与
キーボード操作用に focus-visible でフォーカスリングを表示
nav / section に aria-label を設定
5. スマホ対応
商品一覧は画面幅に応じて 2 / 3 / 4 列に切り替え
カテゴリが多い場合は横スクロールで表示
チーム開発で学んだこと
コードレビューへの対応: カテゴリフィルタは 2 回のレビュー指摘を受けて修正しました。指摘の意図を確認しながら直すことで、命名や責務の分け方を学びました。
コンフリクトの解消: 他のメンバーと同じ ProductCard を編集してコンフリクトが起きました。develop を取り込んで解消し、マージ記号の消し忘れも修正しました。
ブランチ運用: 画面ごとに feature ブランチを切り、こまめに develop を取り込んで差分を小さく保ちました。
ローカルでの起動方法
# Node.js 22 推奨（20.9 以上）
corepack enable
pnpm install
cp .env.example .env.local   # NEXT_PUBLIC_API_BASE を設定
pnpm dev                     # http://localhost:3000
※ 商品データの表示には、別途バックエンド API（http://localhost:8080）の起動が必要です。
